# ADR-000: 개발 환경과 도구 결정

- 상태: 결정됨
- 날짜: 2026-10-22
- 관련 스텝: S00

## 배경

분리배출 로봇팔 프로젝트를 시작하며 장비, 네트워크, 화면 보기, LLM, 기록 도구를
정해야 한다. 원본 가이드라인은 SO-101 로봇팔을 기준으로 했지만, 이 프로젝트는
보유 중인 myCobot 280 Jetson Nano를 쓴다.

## 이유와 대가

### 1. 엔드이펙터
- 이유: 그리퍼만으로는 병 몸통·캔처럼 넓은 물체를 집기 어렵다. 흡착은 평평한 면(캔 윗면, 펼친 종이팩)에 강하다.
- 대가: 한 번에 하나만 장착할 수 있다. 자동 교체 장치가 없다.
- 확인할 것: 그리퍼 모델명과 집기 폭 [확인 필요], 흡착 펌프의 Jetson Nano 버전 연결·제어 방법 [확인 필요]

### 2. 네트워크
- 이유: 같은 공유기 안에서는 지연이 가장 작고 VPN이 필요 없다.
- 대가: 장소를 옮기면 설정을 다시 해야 한다.

### 3. 카메라
- 이유: Jetson Nano는 Ubuntu 18.04라 ROS 2 Jazzy를 돌릴 수 없다. Docker로 구버전 ROS 2를
  돌리면 영상이 느리다는 보고가 있고, 다른 버전 ROS 2 사이 통신은 보장되지 않는다.
- 대가: 전송 지연, 네트워크 사용량, Jetson 부하, 시계 차이.
- 대응: 로봇이 멈춘 상태에서 찍고 움직인다. 유선 연결. 지연·부하는 S23에서 측정.

### 4. 서버
- 대가: 백업과 보안은 내 책임. 코드는 매일 GitHub에 올린다.

### 5. 화면 보기
- 확인할 것: 서버에 모니터가 연결되어 있는가 [확인 필요] → 없으면 HDMI 더미 플러그 검토

### 6. LLM
- 이유: 설치가 간단하고 성능이 검증되어 있어 학습 초기의 변수를 줄인다.
- 대가: 비용, 인터넷 의존, 외부 전송.
- 규칙: API 키는 `.env`에만 두고 절대 커밋하지 않는다. 사용 금액 한도를 설정한다.

### 7. 기록
- 규칙: 원본은 GitHub, 블로그는 읽기 좋게 다듬은 버전. 블로그 글에는 GitHub 링크를 단다.
